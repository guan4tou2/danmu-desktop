### 2.2 盤點出的問題

**(a) 設定不落地。** 「即時套用」只寫進 `app.config`，重啟後回到環境變數，畫面上沒有任何提示。頁尾有一顆「匯出 .env 片段」，要人自己把數值貼回環境變數。

**(b) 畫面顯示的不是實際生效的值。**

- 四列輸入框的初始值是前端寫死的，不讀伺服器目前的值。`/admin/metrics` 其實有回 `rate_limit_config`，這頁沒有用。
- 同一個預設值在五個地方各寫一份、互相矛盾：

  | | `config.py` | 後台頁初始值 | 「重設預設」 | `metrics.py` `_RATE_DEFAULTS` | `.env.example` |
  |---|---|---|---|---|---|
  | API | 120 | 30 | 30 | 30 | 30 |
  | ADMIN | 300 | 300 | 60 | 60 | 60 |

- 「重設預設」只改輸入框、不呼叫任何 API。
- 系統 › Fire Token 頁的「200/min」、設定精靈的「每分鐘最多 20 則」、登入頁的「5 次」都是寫死的字串。

**(c) 統計不含真正的彈幕流量。** 統計只在 `rate_limit` 裝飾器裡記錄，而 `/fire` 刻意不走裝飾器、走 `enforce_fire_rate_limits`，後者不記錄。結果 fire 那一列的用量條、走勢圖、違規列表、「套用建議」，以及 Fire Token 頁的用量圖，都只算到 `/poll/vote` 與外部 Webhook 進來的訊息，不含 `/fire` 本身。

**(d) 彈幕樣式頁的摘要卡標錯了。** 「每人每分鐘」顯示的是每個 IP 的 `FIRE_RATE_LIMIT`；「Cooldown 時間」顯示的是 `FIRE_RATE_WINDOW`；「全域每秒」「Burst」固定顯示「—」；提示文字寫「超過自動排隊」，實際是回 429；頁腳寫「修改後即時生效」，但這張卡不能修改。

**(e) 空殼。** login 列的「鎖定秒數」不會送出，伺服器也沒有對應設定（欄位的 title 自己寫著「UI-only」）。

**(f) 有在執行但沒有畫面。** 「同時在畫面上的彈幕數」預設 20 且超過就丟棄，正式環境一直在生效，但後台已經沒有任何地方能看到或調整（`sec-onscreen-limits` 只剩 `admin.js:476` 排序清單裡的一個 id）。`ViewerFireCooldownSec` 同樣沒有控制項。

**(g) 「觀眾多快能送一則」同時有四處在管**：每 IP、每指紋（環境變數）、封鎖規則的頻率類型（每指紋）、觀眾端冷卻。其中每指紋有兩套並存。

**(h) 429 不帶 `Retry-After`。** 觀眾頁會讀這個標頭決定是倒數還是跳全螢幕限流畫面，但伺服器從來不送（`server/app.py:295-297`）。`config.py:262-263` 與 `managers/settings.py:40` 的註解寫「Server-side 429 retry-after always wins」，與實際不符。

**(i) 名稱互相混淆。** 這頁的「IP 白名單」是略過限流用的；系統 › 安全的「IP 白名單」是限制誰能進後台，是兩份不同的清單。scope 叫 fire，但調它會同時影響 `/poll/vote` 與外部 Webhook 進來的訊息（三者共用同一個計數桶）。

**(j) 會把自己鎖在外面。** 「後台動作」上限最小可以設成 1，而套用上限的端點本身也受這個上限管。

### 2.3 目標形狀（建議）

審核 › 發送上限這一頁只留**一個主動作：設定觀眾多快能送一則**。

```
發送上限

  對象 [ 每位觀眾 ▾ ]   最多 [ 20 ] 則 ／ [ 60 秒 ▾ ]        [ 儲存 ]
        ├ 每位觀眾（同一網路位址）
        ├ 每個裝置
        └ 全場合計

  送出後冷卻 [ 3 ] 秒
  同時在畫面上最多 [ 20 ] 則 · 超過時 [ 丟棄 ▾ ]

  ▸ 其他請求上限        （一般請求／後台動作／登入嘗試／管理通道，用同一組「對象＋數值」表單）
  ▸ 白名單與黑名單
  ▸ 近期被擋紀錄
```

要點：

- 「對象」選單切換時，數值欄載入**伺服器目前生效的值**。同一個表單元件在「其他請求上限」摺疊區重用，選項換成另外四個對象。
- 設定落地到 `runtime/`（走 `services/json_state.py::JsonState`），環境變數當預設值、檔案覆寫。這是行為改變，見 D1。
- 「送出後冷卻」與「同時在畫面上」兩個本來沒有畫面的設定補上控制項。它們的單位不同（秒、則數），所以不塞進「對象」選單，各自一列。
- 統計改成包含 `/fire`（在 `enforce_fire_rate_limits` 的各個判定點記錄），用量條與違規列表才有意義。
- 彈幕樣式頁「發送與內容限制」摺疊區裡的「速率限制」卡移除（它是標錯的唯讀鏡像），「內容限制」卡留著。見 D5。
- 封鎖規則的「頻率」類型這一批**不動**（它能設期限與本場次，是真的功能）。見 D4。

### 3.2 盤點出的問題

**(a) 同一份資料有多個出口，欄位各不相同。**

- 彈幕紀錄有 4 個畫面出口（精靈、場次面板、場次詳情、搜尋），再加一個**沒有任何畫面在用**的後端端點 `GET /admin/history/export`。四種 CSV 的欄位都不一樣。
- 操作紀錄有 2 個出口，一個篩選、一個不篩選。
- `/get_settings` 有 3 個出口：設定快照（`{settings}`）、彈幕樣式匯出（`{options}`）、完整備份裡的 `runtime/settings.json`。彈幕樣式頁匯出的檔丟進「還原設定檔」會被拒絕：外層的 `exported_at` 會被當成未知的設定鍵，回 400（由程式碼確認，未實跑；`admin-backup.js:215`、`managers/settings.py:276-278`）。也就是說那顆匯出鈕產出的檔案沒有地方能匯入。

**(b) 「完整備份」不完整。** 下列資料不在任何一種後台備份裡：

| 資料 | 位置 |
|---|---|
| 彈幕紀錄 | `runtime/danmu_history.jsonl` |
| 場次歸檔 | `runtime/sessions_archive.jsonl` |
| 操作紀錄 | `runtime/audit.log` |
| 重播註記 | `runtime/replay_annotations.log` |
| 自訂主題 | `runtime/themes/*.yaml` |
| 上傳的字型 | `user_fonts/` |
| 活動 Logo | `runtime/event_logo.*` |
| 投票圖片 | `runtime/polls/` |

原因是完整備份只收 `runtime` 下的 `.json`、`effects` 下的 `.dme`、外掛的 `.py`（`services/backup.py:92-96`）。命令列的 `scripts/backup.sh` 與後台的「完整備份」互不包含：腳本收了整個 `runtime`、字型與 `static`（所以上表多數資料它有），但沒收 `server/effects` 與 `server/plugins`；後台備份則相反。目前沒有任何一種備份是完整的。

**(c) 時間軸匯出精靈大半是空殼。**

- 「自訂」範圍沒有日期輸入框，實際等於 24 小時；「昨天」是 48 小時、會連今天一起算。
- 內容篩選判斷的欄位（`is_poll`、`muted`、`banned`）在紀錄裡不存在：「投票」「已遮蔽」開關沒有作用，關掉「原文」會把所有紀錄濾光。
- 三種格式的說明與 SRT 徽章不會顯示（程式讀 `desc`／`badge`，資料定義的是 `descKey`／`badgeKey`）。
- 要求 10000 筆，後端截到 5000。
- 記憶體預設只留 24 小時的紀錄，所以「近 7 天」拿到的通常更少。啟動時從檔案載入不依時間過濾，而清理每小時才跑一次，所以重啟後約一小時內拿得到比較舊的紀錄，之後就被清掉——同一個範圍在不同時間匯出，結果不一樣（`services/history.py:74-110`、:385-396）。
- 「最近匯出」清單只存在瀏覽器的 localStorage。

**(d) 文案與實作不符。**

| i18n key | 文案說 | 實際 |
|---|---|---|
| `historyV2PrivacyBody` | 含 IP／指紋的匯出檔 24 小時後自動刪除 | 檔案是瀏覽器直接下載，沒有任何刪除機制 |
| `backupFullPackRestoreNote` | 中途失敗不會留下半套狀態 | 逐檔替換，沒有整包回滾 |

| `backupSettingsSnapshotDesc` | 審核、顯示層、觀眾頁、主題 | 只有 11 個鍵（10 個樣式相關的，加上送出後冷卻秒數） |

| `mnavDescHistory` | 場次 · 審計 · 重播 · 匯出 | 重播分頁與時間軸匯出都已移走 |

**(e) 上傳大小上限互相打架（推論，未實測）。** 完整備份前端與服務層都擋 16 MB、素材包擋 64 MB，但 Flask 的 `MAX_CONTENT_LENGTH` 是全站 15 MB，沒有任何路由另外覆寫（`config.py:91`），超過 15 MB 的上傳應該會先被拒絕。若屬實，素材包超過 15 MB 就還原不回去。實際回什麼錯誤要實跑才知道。

**(f) 其他空殼。** 危險區的範圍下拉只有「全部」一個選項；`#/replay` 別名指向已不存在的分頁；七個找不到使用處的 i18n key（`noRecordsToExport`、`jsonTimelineExported`、`exportFailed`、`sessionDetailExportJsonBtn`、`histEmptyDesc`、`navAccordionBackup`、`uploadDme`）。

### 3.3 目標形狀（建議）

一個「匯出與備份」頁（沿用 `#/system/backup`），**一個主動作：下載**。

```
匯出與備份

  要匯出 [ 完整備份 ▾ ]                                   [ 下載 ]
          ├ 完整備份
          ├ 設定
          ├ 素材
          ├ 彈幕紀錄
          └ 操作紀錄
  （依選項出現的欄位）
    完整備份：☐ 包含連線密碼與 token
    彈幕紀錄：範圍 [ 這一場 ▾ ]  格式 [ CSV ▾ ]  ☐ 包含觀眾 IP 與裝置識別
    操作紀錄：範圍 [ 近 24 小時 ▾ ]  格式 [ JSON ▾ ]

  ▸ 還原      （一個上傳框，依檔案內容自動判斷是設定、完整備份還是素材包 → 預覽 → 套用）
  ▸ 清除資料  （清除彈幕紀錄、重置為出廠設定）
```

要點：

- 「要匯出什麼」是那個把五個出口併成一處的選項。選項下方只出現該類型用得到的欄位。
- 彈幕紀錄一律由伺服器產生（用現有的場次匯出端點與 `/admin/history/export`），**欄位統一成一套**。精靈整個由這個表單取代；它真正有用的三件事（範圍、格式、是否含個資）都保留。
- 還原三個上傳框併成一個，由檔案內容判斷類型（設定是 JSON；兩種 tar.gz 用內含的 manifest 區分）。預覽與套用的流程、`restart_required` 的提示都沿用現有行為。
- **情境內的匯出保留**：場次列的「匯出 ›」、搜尋結果的「匯出結果 CSV」、投票結果的匯出，匯出的是「畫面上這一份」，是真的功能。但它們改成呼叫同一套匯出，欄位一致。見 D9。
- 重複的出口收掉：場次詳情的「只有 CSV」按鈕改成開同一個面板；系統事件頁的匯出移除（與操作紀錄同一份資料）；彈幕樣式頁的「匯出 JSON」移除或改成與設定快照同一格式（D10）；投票深度分析的匯出與投票頁對齊。

- 輸入框字級在手機必須是 16px（`--text-subhead`），否則 iOS 點輸入框會自動放大畫面。
- CSP 不允許 inline 事件處理器。
- 桌面兩欄版面裡，主欄的每個直接子元素都要指定欄位，否則會被排到樣式面板那一欄。
- 鍵盤彈出時送出列會改成固定定位並跟著鍵盤高度（`main.js:2709-2745`）；改成常態固定後這段要一起重寫，並在真機上驗證。

## 9. 每一批怎麼做

流程本體在 [agent-ops](../agent-ops/README.md)，這裡只列順序與這幾批實際踩到的事。

### 9.1 順序

1. **拍板**：把該批在 §7 的決定逐項確認。
2. **實測推論**：本文件標「推論」「未確認」的地方，先在本機實跑確認，結果寫回對照表。
3. **凍結基準**：改動前跑一次相關測試並留下輸出；UI 批次另外留桌面與手機寬度的截圖。
4. **實作**：依 [10-model-dispatch.md](../agent-ops/10-model-dispatch.md) 派工，派工時一律指定模型與 effort。
5. **重建生成物**：`admin.bundle.js`、i18n（**兩支**產生器）、`tailwind.css`、`viewer-base.css`。
6. **五道閘**：server pytest 全套、browser 測試、兩邊的 jest、`make lint-css`、black＋isort＋flake8。
7. **獨立複核**：由沒有參與實作的 agent 讀 diff 並實跑，等級不低於實作者。複核只讀、不連外、不碰正式環境。
8. **PR → CI 全綠 → 合併**。
9. **發版**：版號改 `danmu-desktop/package.json`、`danmu-desktop/package-lock.json`（兩處）、`server/config.py:APP_VERSION`，四處同一個值；CHANGELOG 的 `[Unreleased]` 改成版本與日期；`TODOS.md` 把完成的項目移到 Completed。
10. **部署與冒煙測試**：Python 有改動時要重建映像，不是只 pull 加重啟。部署後確認版本號、主要頁面與端點的回應碼。
